## 1. 윈도우가 느릴 때, 디스크 100%부터 확인하기

가상의 월요일 아침, 저는 앱 대신 로딩 표시와 눈싸움을 하고 있습니다. 평소 쓰던 앱이 좀처럼 열리지 않아 작업 관리자를 켰더니 디스크 사용률이 100%입니다. 설명을 위한 상황이며, 제가 실제로 겪은 수리 경험이라는 뜻은 아닙니다. SysMain(이전 이름은 Superfetch)을 범인으로 단정하기 전에 어떤 프로세스가 실제로 드라이브를 쓰는지 확인하겠습니다. 100%는 디스크가 바쁜 시간의 비율을 보여줄 뿐, 원인이나 전송 속도를 직접 알려주지는 않습니다.

먼저 사용량이 높은 프로세스와 시각, 당시 작업을 적고 SysMain을 잠시 중지한 뒤 같은 작업을 반복해 비교합니다. 한 번의 순간값으로 서비스를 끄는 것보다 조건을 맞춘 비교가 더 믿을 만한 단서가 됩니다.

## 2. SysMain과 다른 디스크 작업 구별하기

`Ctrl`+`Shift`+`Esc`를 눌러 작업 관리자를 열고 **프로세스** 탭에서 **디스크** 열을 선택합니다. 사용량이 높은 항목의 이름과 수치, 문제가 나타난 시간, 당시 실행한 작업을 적어 두세요. 사용률이 잠깐 높아졌다 낮아지는지, 같은 작업을 할 때마다 높게 유지되는지도 함께 봅니다. 한 번의 순간값보다 반복되는 양상이 더 유용합니다.

SysMain이 의심된다면 `Service Host: SysMain` 또는 Windows 표시 언어에 따라 이에 해당하는 **서비스 호스트** 항목이 디스크 사용량과 함께 두드러지는지 살펴봅니다. 표시 이름만으로 판단하기 어렵다면 작업 관리자의 **세부 정보** 탭과 **서비스** 탭에서 PID(프로세스 ID)가 일치하는지 확인할 수 있습니다. 버전이나 화면 구성에 따라 표시 방식은 다를 수 있습니다.

반대로 다른 앱이나 Windows 작업이 디스크 사용량을 차지하고 있다면, SysMain을 멈춰도 변화가 없을 수 있습니다. 서비스가 실행 중인지와 디스크를 실제로 많이 사용하는지는 별개의 확인 사항입니다. 따라서 저는 SysMain을 끄기 전에 작업 관리자에서 확인한 프로세스와 서비스 목록을 서로 비교하겠습니다.

## 3. SysMain을 안전하게 비교 진단하기

저는 서비스를 곧바로 사용 안 함으로 바꾸기보다, 현재 상태를 기록하고 같은 작업을 기준으로 중지 전후를 비교하겠습니다.

1. 작업 관리자에서 디스크 사용량이 높은 프로세스 이름과 사용률을 기록합니다. 평소 문제가 생기는 작업을 할 때도 같은 항목이 높은지 확인하세요. SysMain이 눈에 띄지 않고 다른 프로세스가 사용량을 차지한다면, SysMain 중지는 우선순위가 아닙니다.
2. `Win`+`R`을 누르고 `services.msc`를 입력한 뒤 **서비스**에서 **SysMain**을 찾습니다. 현재 상태와 시작 유형을 기록하세요. 이름이 다르게 보이거나 해당 항목인지 확신할 수 없다면 변경하지 말고 Windows 서비스 목록에서 항목을 다시 확인합니다.
3. SysMain이 실행 중이고 원인 여부를 비교하려는 경우, SysMain을 마우스 오른쪽 버튼으로 클릭해 **중지**를 선택합니다. 이후 문제가 나타나던 작업을 같은 방식으로 해 보며 작업 관리자의 디스크 사용률과 반응을 기록하세요. 잠깐의 변화만으로 결론 내리지 말고, 가능한 한 같은 조건에서 비교합니다.
4. 중지 전보다 사용량이 반복해서 낮아지면 SysMain이 원인에 기여했을 가능성이 있습니다. 다만 이 결과만으로 확정하지는 마세요. 차이가 없거나 앱 실행이 불편해지면 서비스 창에서 SysMain을 다시 **시작**합니다. 시험을 마친 뒤 시작 유형이 원래 설정과 같은지도 확인하세요.

## 4. 설정 변경은 최소화하고, 반복되면 점검하기

진단을 위해 잠시 중지하는 것과 시작 유형을 **사용 안 함**으로 바꾸는 것은 다릅니다. 먼저 일시 중지로 비교하고, 효과를 확인하지 않은 채 시작 유형을 영구적으로 바꾸지는 마세요. SysMain 동작이나 앱 반응이 달라질 수 있습니다. 이 확인에는 레지스트리 편집이 필요하지 않으므로, 진단 단계에서 레지스트리 값을 수정할 이유도 없습니다.

SysMain을 중지해도 디스크 사용량이 비슷하다면 서비스를 계속 껐다 켜기보다 작업 관리자로 돌아가 실제 사용량이 높은 프로세스를 확인하세요. 문제가 나타난 시간대와 프로세스 이름을 다시 기록하고, 평소 작업에서도 같은 현상이 반복되는지 살펴봅니다. 단 한 번의 비교에서 달라졌더라도 다른 작업이 동시에 끝났을 수 있으므로, 그 결과만으로 설정을 고정하지 않는 것이 좋습니다.

파일을 열거나 저장하는 데 문제가 생기거나 디스크 오류가 함께 표시된다면, 서비스 설정을 더 바꾸기 전에 중요한 파일을 백업하세요. 반복적인 멈춤이나 오류가 계속되면 PC 제조사 지원 또는 신뢰할 수 있는 점검 담당자에게 문의하는 편이 안전합니다. SysMain이 원인처럼 보였나요, 아니면 작업 관리자에서 다른 프로세스가 더 두드러졌나요?

### 결과에 따라 다음 점검을 선택하기

이 비교 결과는 확정 판정이 아니라 단서로 봅니다. SysMain을 중지해도 같은 앱이나 Windows 작업이 계속 상위에 있다면 그 작업을 확인하거나, 진행 중인 것이 분명한 업데이트·검사가 끝날 때까지 기다립니다. 관계없는 서비스를 중지해도 원인을 찾는 데 도움이 되지 않습니다. 같은 작업에서 디스크 활동이 낮아지고 SysMain을 다시 시작한 뒤 되돌아온다면 서비스가 영향을 줄 가능성이 있습니다. 영구 설정을 바꾸기 전에 비교를 반복하세요. 처음부터 SysMain이 중지되어 있었다면 이 방법으로는 차이를 확인할 수 없습니다.

원인이 뚜렷한 프로세스 없이 드라이브가 계속 바쁘다면 Windows 검색에서 `resmon`을 실행해 **리소스 모니터**의 **디스크** 탭과 파일 경로를 느려지는 순간에 확인합니다. 메뉴 이름은 Windows 버전에 따라 다를 수 있습니다. 저장 장치 상태 경고가 표시되거나 멈춤·오류가 계속되면 레지스트리 조정보다 중요한 파일 백업과 드라이브 점검을 먼저 하세요. Microsoft의 [저장 장치 중요 경고 안내](https://support.microsoft.com/en-us/windows/experience/storage-filemanagement/what-to-do-about-a-critical-warning-for-a-storage-device)에서 경고 확인 방법을 볼 수 있습니다.

## 5. SysMain과 디스크 사용량 100% FAQ

**Q1.** 디스크 사용량이 100%이면 SysMain이 원인인가요?

**A1.** 아닙니다. 작업 관리자에서 해당 시간에 디스크를 많이 사용하는 프로세스를 확인해야 합니다. SysMain이 실행 중이라는 사실만으로 원인이라고 판단할 수 없습니다.

**Q2.** SysMain을 중지해 원인인지 확인해도 되나요?

**A2.** 서비스 상태를 기록한 뒤 일시적으로 중지하고, 같은 작업에서 전후 사용량을 비교할 수 있습니다. 차이가 없거나 불편해지면 다시 시작하세요. 처음부터 시작 유형을 사용 안 함으로 바꿀 필요는 없습니다.

**Q3.** SysMain을 중지했는데도 디스크 사용량이 계속 높으면 어떻게 하나요?

**A3.** 작업 관리자에서 다른 사용량 높은 프로세스를 확인하고, 프로세스 이름과 문제가 생긴 시간대를 기록하세요. 파일 접근 문제나 디스크 오류가 함께 나타나거나 증상이 반복되면 중요한 파일을 백업한 뒤 추가 점검을 받으세요.
