### なぜ起きる？アップデートが100%でスタックする3つの原因

まずは敵を知ることから始めましょう。なぜ進捗率が100%に達しているのに完了しないのでしょうか。現場で特定された主な原因は以下の3つです。

## 1. ダウンロードした更新キャッシュの破損

   Microsoftのサーバーから取得したパッケージの一部が、通信の揺らぎなどで破損しており、インストール処理の最終検証（コミット）で無限ループに入っている。

## 2. Windows Update関連サービスのデッドロック

   `wuauserv`（Windows Update）などのバックグラウンドサービスが競合を起こし、ファイルロックが解除されなくなっている。

## 3. サードパーティ製セキュリティソフトの干渉

   最終段階でのシステムファイルの書き換えを、過剰な常駐セキュリティが不正アクセスと誤認してブロックし続けている。

### 超高速1分解決！キャッシュフォルダリセットの2ステップ

泥沼の試行錯誤はここまでです。破損したキャッシュをきれいに掃除し、アップデートプロセスを強制的にリセットする具体的な手順を解説します。

## ステップ1：セーフモードまたはタスクの停止によるサービス無効化
まずは、ロックされている更新ファイルを解放するために、バックグラウンドの関連サービスをストップさせます。

1. スタートボタンを右クリックし、「ターミナル（管理者）」または「コマンドプロンプト（管理者）」を起動します。

## 2. 以下のコマンドを順番に入力し、Enterキーを押してサービスを停止させます。

```cmd
net stop wuauserv
net stop cryptSvc
net stop bits
net stop msiserver
```

## ステップ2：SoftwareDistributionフォルダのリセット
Windowsがダウンロードしたアップデートの一時保存場所である「SoftwareDistribution」フォルダと「Catroot2」フォルダをリネーム（または削除）することで、完全にフレッシュな状態を作ります。

引き続き管理者用コマンドプロンプトで、以下のコマンドを実行します。

```cmd
ren C:\Windows\SoftwareDistribution SoftwareDistribution.old
ren C:\Windows\System32\catroot2 Catroot2.old
```

この処理により、古い破損キャッシュが無効化され、新しく綺麗なキャッシュフォルダが自動生成される準備が整います。

仕上げに、停止したサービスを再起動します。

```cmd
net start wuauserv
net start cryptSvc
net start bits
net start msiserver
```

ここまで完了したら、PCを再起動してください。驚くほどスムーズにアップデートが再開、あるいは正常なデスクトップ画面へと復帰します。

### よくある質問（FAQ）

**Q1. **コマンドプロンプトで「アクセスが拒否されました」とエラーが出ます。

A1. コマンドプロンプトを「管理者として実行」していないことが原因です。必ずスタートメニューから右クリックし、管理者権限で立ち上げ直してください。

**Q2. **キャッシュをクリアしても、次回のアップデートでまた100%で止まります。

A2. OSのシステムファイル自体が破損している可能性が高いです。管理者権限のターミナルで `DISM.exe /Online /Cleanup-image /Restorehealth` を実行したあと、`sfc /scannow` をかけてシステムを修復してから再度お試しください。

**Q3. **作業中に強制終了した場合、データは消えてしまいますか？

A3. アップデートの最中であっても、ユーザーのドキュメントやデスクトップ上のファイルが直接消えることは稀ですが、システムファイルが壊れて起動不可になるリスクはゼロではありません。重要な仕事の前には必ず外部ストレージやクラウドへのバックアップを習慣づけましょう。
