## 문제 증상 및 원인 분석

Windows 운영체제를 사용하는 시스템에서 C드라이브의 여유 공간 부족 경고(붉은색 막대 표시)는 단순한 저장 공간 부족을 넘어 시스템 전체의 입출력 병목 현상과 블루스크린(BSOD)을 유발하는 치명적인 장애 요소입니다. C드라이브 용량이 한계치(잔여 공간 10% 미만)에 도달하면 가상 메모리(Paging File) 할당 실패, 윈도우 업데이트 설치 중단, 애플리케이션 충돌 현상이 복합적으로 발생합니다.

### 1. 소프트웨어적 원인
* **사용자 및 시스템 임시 파일 누적**: 응용 프로그램 설치, 압축 해제, 캐시 데이터 축적 과정에서 생성된 `%temp%` 및 `C:\Windows\Temp` 디렉터리의 휘발성 파일들이 프로세스 종료 후에도 자동 삭제되지 않고 잔류합니다.
* **Windows Update 캐시 잔류**: `C:\Windows\SoftwareDistribution\Download` 폴더에 과거 누적 업데이트 및 패치 설치 파일이 수 기가바이트(GB) 단위로 방치됩니다.
* **최대 절전 모드 파일(hiberfil.sys) 및 가상 메모리(pagefile.sys)**: 데스크톱 환경에서도 기본 활성화된 최대 절전 모드는 시스템 RAM 용량에 비례(RAM 32GB 기준 약 13~25GB)하여 고정 스토리지를 강제 점유합니다.
* **Windows.old 및 시스템 복원 지점**: 대규모 기능 업데이트 후 생성되는 이전 버전 백업과 VSS(볼륨 섀도 복사본) 스냅샷이 수십 기가바이트를 지속적으로 소모합니다.

### 2. 하드웨어 및 파일 시스템 차원의 영향
* **SSD 쓰기 증폭(Write Amplification) 및 성능 저하**: SSD는 블록(Block) 단위로 데이터를 지우고 페이지(Page) 단위로 씁니다. 여유 공간이 15~20% 이하로 떨어지면 컨트롤러의 TRIM 명령 수행 및 가비지 컬렉션(Garbage Collection) 효율이 급감하여 쓰기 속도가 최대 70% 이상 곤두박질칩니다.
* **웨이 아웃(Wear-out) 가속화**: 유효 셀이 부족해지면 특정 플래시 메모리 영역에만 쓰기 작업이 집중되어 SSD의 기대 수명(TBW)을 급격히 단축시킵니다.

## 단계별 해결 가이드

단순히 휴지통을 비우는 방식으로는 숨겨진 시스템 정크 파일을 회수할 수 없습니다. 안전하면서도 확실하게 수십 기가바이트의 용량을 확보하는 정밀 절차입니다.

### 1단계: Windows 기본 고급 디스크 정리 및 시스템 파일 소각

Windows에 내장된 '디스크 정리' 도구를 고급 권한으로 실행하여 구형 업데이트 파일과 로그를 삭제합니다.

1. **실행 창 호출**: 키보드의 `Windows Key + R`을 누릅니다.
2. **명령어 입력**: `cleanmgr.exe`를 입력하고 Enter를 누릅니다. C드라이브를 선택하고 확인을 클릭합니다.
3. **시스템 파일 정리 활성화**: 하단의 **[시스템 파일 정리]** 버튼을 클릭합니다. (관리자 권한으로 검사가 재수행됩니다.)
4. **삭제 대상 선택**:
   * **Windows 업데이트 정리** (수 GB 이상 확보 가능)
   * **이전 Windows 설치** (존재할 경우 최대 20~30GB 확보)
   * **임시 Windows 설치 파일**
   * **디바이스 드라이버 패키지**
   * **전달 최적화 파일**
5. **확인**을 눌러 영구 삭제를 진행합니다. (CPU 및 디스크 점유율에 따라 5~20분 소요)

### 2단계: 핵심 임시(Temp) 디렉터리 및 업데이트 캐시 강제 수동 정리

프로세스 락(Lock)이 걸리지 않은 유휴 캐시 파일을 직접 제거하는 단계입니다.

#### 1) 사용자 및 윈도우 Temp 청소
1. `Windows Key + R`을 누르고 `%temp%`를 입력 후 Enter를 누릅니다.
2. 폴더 내 모든 파일 선택(`Ctrl + A`) 후 영구 삭제(`Shift + Delete`)를 실행합니다.
   * *주의: '현재 사용 중인 파일' 안내 창이 뜨면 **[모든 현재 항목에 대해 수행]** 체크 후 **[건너뛰기]**를 클릭합니다.*
3. 다시 `Windows Key + R`을 누르고 `C:\Windows\Temp`를 입력하여 진입합니다.
4. 관리자 권한 안내 창이 뜨면 [계속]을 누르고, 내부 파일 전체를 위와 동일하게 삭제(건너뛰기 포함)합니다.

#### 2) Windows Update 캐시 초기화
1. 작업 표시줄 검색창에 `cmd`를 입력하고, **[명령 프롬프트]를 우클릭하여 [관리자 권한으로 실행]**합니다.
2. 업데이트 관련 백그라운드 서비스를 일시 중지합니다:
   ```cmd
   net stop wuauserv
   net stop bits
   ```
3. 탐색기(`Windows Key + E`)를 열어 `C:\Windows\SoftwareDistribution\Download` 경로로 이동합니다.
4. 폴더 내부의 모든 파일과 폴더를 삭제합니다. (이 파일들은 이미 설치되었거나 손상된 설치 파일이므로 삭제해도 시스템에 무해합니다.)
5. 중지했던 서비스를 다시 시작합니다:
   ```cmd
   net start bits
   net start wuauserv
   ```

### 3단계: 시스템 예약 공간(최대 절전 모드 해제) 즉각 회수

데스크톱 PC를 사용하거나 최대 절전 모드를 쓰지 않는 노트북 사용자의 경우, RAM 용량만큼 C드라이브를 점유하는 `hiberfil.sys`를 제거하여 즉시 10~30GB를 확보할 수 있습니다.

1. **관리자 권한 명령 프롬프트**를 실행합니다.
2. 아래 명령어를 입력하고 Enter를 누릅니다:
   ```cmd
   powercfg -h off
   ```
3. 어떠한 메시지도 출력되지 않고 다음 입력 프롬프트로 넘어가면 정상 처리된 것입니다.
4. 탐색기에서 C드라이브를 확인하면 `C:\hiberfil.sys` 파일이 즉시 증발하며 해당 용량이 사용 가능 공간으로 환원됩니다.
   *(추후 다시 활성화하려면 `powercfg -h on`을 입력하면 됩니다.)*

## 실무자 팁 및 주의사항

시스템 공간을 확보하려는 조급함 때문에 `C:\Windows\System32` 내부의 파일을 건드리거나, 용량이 크다는 이유로 `C:\Users\[사용자명]\AppData` 폴더 자체를 통째로 삭제하는 행위는 절대 엄금해야 합니다. AppData 폴더를 통째로 삭제하면 설치된 모든 소프트웨어의 프로필, 라이선스 인증 정보, 브라우저 북마크, 로컬 데이터베이스가 파괴되어 OS를 포맷해야 하는 상황에 직면합니다. 

또한, SSD 기반 시스템에서는 TRIM 기능이 정상 동작하고 SSD 컨트롤러의 오버 프로비저닝(Over-Provisioning) 공간이 유지되도록 **최소 전체 용량의 15% 이상을 상시 여유 공간으로 확보**해 두는 것이 하드웨어 수명 연장과 성능 유지의 절대적인 원칙입니다. 상용 '레지스트리 청소기' 프로그램의 무분별한 사용은 불필요한 레지스트리 키뿐만 아니라 시스템 드라이버 연동 경로까지 훼손할 수 있으므로 권장하지 않습니다.

## 자주 묻는 질문 (FAQ)

### Q1. Temp 폴더를 정리할 때 "파일이 사용 중이므로 작업을 완료할 수 없습니다"라는 오류는 왜 발생하나요?
현재 백그라운드에서 실행 중인 백신, 브라우저, 시스템 프로세스가 해당 임시 파일을 읽기/쓰기 모드로 핸들링(Lock)하고 있기 때문입니다. 이는 정상적인 시스템 보호 메커니즘입니다. 삭제 창에서 **'모든 현재 항목에 대해 수행'을 체크한 뒤 '건너뛰기'**를 선택하여 락이 걸리지 않은 나머지 유휴 캐시 파일들만 정리하면 시스템 충돌 없이 안전하게 용량을 확보할 수 있습니다.

### Q2. `pagefile.sys` 파일도 지워서 용량을 더 확보할 수 있나요?
`pagefile.sys`는 실제 물리적 RAM이 부족할 때 디스크를 가상 메모리로 활용하는 필수 시스템 파일입니다. 이를 강제로 완전히 비활성화(삭제)하면 RAM 용량이 충분하더라도 대용량 렌더링, 고사양 게임 구동, 또는 가상 머신(VM) 실행 시 예기치 못한 메모리 부족(OOM) 오류로 프로그램이 튕기거나 OS 크래시가 발생합니다. 권장 조치법은 pagefile을 완전 삭제하는 것이 아니라, 드라이브가 2개 이상일 경우 가상 메모리 페이징 파일의 위치를 C드라이브(SSD)에서 D드라이브 등 보조 드라이브로 이전 설정하는 것입니다.

### Q3. C드라이브 용량을 정리했는데 며칠 지나면 다시 빨간색으로 가득 찹니다. 원인이 무엇인가요?
세 가지 원인을 집중 점검해야 합니다. 첫째, **복원 지점(System Restore Points)** 할당 공간이 과도하게 잡혀 있어 Windows가 스냅샷을 계속 누적하는 경우입니다(`vssadmin list shadowstorage` 명령어로 점검 가능). 둘째, **클라우드 스토리지(OneDrive, Google Drive, Dropbox 등)**의 '로컬 동기화' 설정이 켜져 있어 클라우드 파일이 C드라이브에 이중 다운로드되는 경우입니다. 이 경우 클라우드 설정에서 '요청 시 파일 제공(온디맨드)' 기능을 켜야 합니다. 셋째, 특정 응용 프로그램(주로 개발 툴, Adobe 계열 스크래치 디스크, 엔비디아 드라이버 셰이더 캐시)의 로그 폭주 현상일 수 있으므로 'TreeSize Free'나 'WizTree' 같은 전문 디스크 점유율 시각화 유틸리티를 관리자 권한으로 실행하여 실시간으로 이상 증식하는 특정 폴더 경로를 추적해야 합니다.
